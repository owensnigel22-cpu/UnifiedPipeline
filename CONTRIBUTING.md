# Contributing

Contributions should preserve the project's constrained-recovery and research scope. Do not add an unconstrained address/public-key-hash-to-private-key search feature, network calls, or telemetry.

Before opening a change:

1. Use Python 3.11 or newer and install the development extras with `python -m pip install -e ".[dev]"`.
2. Run `pytest` and `ruff check .` from the project root.
3. Add focused tests for behavior changes, including malformed inputs where applicable.
4. Keep test fixtures synthetic or public; never commit wallet secrets.

Cryptographic reference code must document its assumptions and limitations. Production security claims require independent review and are outside this scaffold's guarantees.

For SHA-256 CNF profiling, the schedule words `W[0..15]` come directly from the block; round 17 is the first round that consumes an expanded schedule word (`W[16]`). The routine VS Code benchmark therefore defaults to rounds 14–16, while tests explicitly cover the 16/17 transition. The benchmark fixes a known input and measures encoder/solver wiring; its timing does not predict unconstrained preimage-search complexity. Modular adders intentionally omit carry-out beyond their configured width.

`sha256_reduced` delegates the standard 64-round hash to Python's platform `hashlib`; custom reduced-round experiments use the Python compressor. That compressor expands the message schedule before the rounds and inlines the fixed SHA-256 rotate operations. In local reduced-32 measurements, 64 KiB took 0.203 s vs. 0.273 s before the change, and 256 KiB took 0.849 s vs. 1.144 s. These are environment-specific timings; no change is made to the standard SHA-256 path, and reduced-round hashing is still much slower than `hashlib`.

The CNF encoder represents a three-input XOR with a direct eight-clause Tseitin gate rather than chaining two XOR2 gates. On the latest local fixed-known-input benchmark (constraints added after construction to compare gate encodings), the direct form used 9,489 vs. 10,776 variables at 14 rounds, and 10,850 vs. 12,329 at 16 rounds; both forms had the same clause count for each round after constant folding. Local solver times varied by round, so this variable reduction is not a claim of universally faster solving. SHA models now also propagate known unit-constrained literals during construction and simplify constant/repeated-input XOR, majority, mux, AND, and OR gates before allocating clauses. For a fully fixed 22-byte message at 16 rounds, local model size fell from 10,850 variables / 52,856 clauses when constrained after construction to 177 variables / 433 clauses when bits were supplied at build time. This is a fixed-input optimization and does not imply a similar reduction for unknown preimage inputs. During construction, internally generated gate clauses skip duplicate literal validation after their inputs have been checked, and signed XOR inputs are canonicalized to reuse equivalent gates. The test suite checks Boolean truth tables, signed literals, modular addition, and reduced-round known-input models.

To compare the direct and chained three-input XOR encodings on the same known-input instances, use `keylab sha256-cnf-benchmark --start-round 14 --end-round 20 --xor3-encoding both --solver kissat --solver cadical --csv-output sha256-benchmark.csv`. Each JSON/CSV row records the encoding, formula size, construction time, DIMACS serialization time and size, solver, solver time, outcome, and candidate validation. One generated formula and one serialized DIMACS string are reused across requested solver runs for that configuration. Use `--xor3-encoding direct` or `chain` to isolate one form. The known input is fixed, so this measures encoder/solver wiring rather than unconstrained preimage difficulty; benchmark output is machine-dependent and not a performance guarantee.

`keylab sha256-backward-ledger --target <64-hex-digest> --message-length 33 --output backward-ledger.json` saves the feed-forward-removed state and up to four numerically reversible SHA-256 A-word steps for a one-block hash. It includes the exact message-schedule dependency graph through the requested rounds and labels values as numerically recovered, symbolically expressed, or unresolved. Pass `--known-message <hex>` to evaluate the padded schedule and check whether that message matches the target digest. The ledger reports the backward A-line boundary separately from the final-round equation `h63 = 0x184a25d4 - W63` for the supplied target. This does not establish `e60 = 0x184a25d4 - W63`; the pasted bridge appears to label the final-round `h63` term as `e60`, and those state words are not interchangeable. The ledger does not calculate equation rank or prove independence, uniqueness, or a hard algebraic obstruction. The supplied Stage 4 transcript's numerical state window can be reproduced with this command; its external pickle-based algebraic core cannot be reproduced without the original artifacts and source. Its reported solver counts are retained with provenance marked unverified. A solver timeout must be interpreted as `UNKNOWN`, not `UNSAT`, and does not diagnose the cause. The CNF ripple adder discards the unused most-significant carry gate; its existing majority encoding already includes standard carry-implication clauses, so extra duplicate clauses are not added.

SHA-256 hash CNF solving supports optional generic input-bit cube-and-conquer: add `--solver <solver> --cube-depth N --parallel-workers P` to partition the first `N` unfixed input bits into `2**N` independent assumption cubes, solved by a process pool. The validated base DIMACS formula is parsed once and sent to each worker during initialization; each queued cube task contains only its assumption literals, avoiding repeated large formula IPC. Each worker still needs to give the solver a complete formula for each independent solve. Cube depth is limited to 16; choose a modest depth because the number of solver jobs doubles with each added bit. The aggregate is `UNSATISFIABLE` only if every cube proves UNSAT; any timeout/unknown without a SAT cube remains `UNKNOWN`. For example: `keylab sha256-cnf --mode hash --target <64-hex-digest> --rounds 14 --message-length 3 --solver kissat --cube-depth 4 --parallel-workers 4 --output model.cnf`. This partitions message input bits, not the internal `W63` schedule word. The `.vscode/launch.json` profile demonstrates a 14-round, three-byte CNF run at depth 4. The pasted `W63 -> e60 -> a56` script is not integrated: its asserted `e60` relation is not established by the project trace and it does not actually invoke a solver or constrain a target output.

`keylab rsa-roundtrip --modulus <n> --public-exponent <e> --private-exponent <d> --message <m>` demonstrates raw modular RSA exponentiation. `keylab rsa-hastad-broadcast` checks the textbook repeated-message case using CRT and an exact integer-root check; it requires at least `e` pairwise-coprime moduli and works only when the same unpadded integer message was reused. `keylab rsa-batch-gcd --modulus <n> ...` reports pairwise shared divisors, including duplicate moduli; it is a diagnostic, not a general factoring algorithm. These commands are educational checks, not production RSA. Python's built-in modular exponentiation is not guaranteed constant-time, so this project does not expose a Python `constant_time_pow` security primitive. `keylab selftest` checks synthetic round-trip and broadcast examples.

`keylab sha256-maj-invert --output <word> --a <word> --b <word>` (or omit either known operand and supply the other two) recovers the omitted operand of the 32-bit SHA-256 majority function where the known inputs differ. Its output includes a determined-bit mask: when the two known bits agree, the output validates that bit but does not determine the omitted input bit. This is local Boolean-gate inversion, not SHA-256 state or hash inversion.

`keylab sha256-ch-invert --output <word> --f <word> --g <word>` analyzes unknown operands of `Ch(e,f,g) = (e & f) | (~e & g)`; any non-empty subset of `--e`, `--f`, and `--g` may be omitted. For each omitted operand it reports recovered bits plus determined/ambiguous masks. It checks all per-bit completions using word-parallel masks, rejects contradictions with known inputs, and does not invent values for ambiguous bits. This is inversion of one Boolean gate, not inversion of SHA-256 rounds or a hash.

Quadratic Boolean equations can be converted to ordinary DIMACS CNF with `keylab mq-cnf --equations equations.json --output model.cnf`. The JSON schema is `{"num_variables": N, "equations": [{"quadratic_terms": [[i, j]], "linear_terms": [k], "rhs": 0}]}` with 1-based input-variable indices and each equation interpreted over GF(2). Product variables are shared, repeated terms cancel, and `x*x` reduces to `x`. The output uses ordinary CNF Tseitin gates, not CryptoMiniSat's native XOR format; rank and equation independence are not computed. Do not load pickle artifacts as equation input.
