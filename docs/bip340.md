# BIP-340 Schnorr signatures and BIP-327 key aggregation

## BIP-340 (`keylab.ec.schnorr`)

```python
from keylab.ec.schnorr import schnorr_public_key, schnorr_sign, schnorr_verify

pk = schnorr_public_key(secret)               # 32-byte x-only key
sig = schnorr_sign(b"any length message", secret)          # fresh aux_rand by default
assert schnorr_verify(b"any length message", sig, pk)
```

- **Messages of any length** are supported, following the December 2022
  revision of BIP-340. Taproot always signs a 32-byte sighash, which is just
  one length. Earlier Keylab releases rejected non-32-byte messages.
- `aux_rand` defaults to 32 fresh random bytes. Passing a fixed value (for
  example 32 zero bytes) is for reproducing test vectors only.
- Signing negates the secret when its point has odd y, derives the nonce from
  `hash_BIP0340/nonce(d ⊕ hash_BIP0340/aux(aux) ‖ P ‖ m)`, and re-verifies the
  signature before returning it.
- Verification rejects `r ≥ p`, `s ≥ n`, keys that do not lift, results at
  infinity, and odd-y `R`.

**Tests**: `tests/test_bip340_vectors.py` runs all 19 official vectors
(signing where a secret key is given, verification for all, including the
"infinite R" and out-of-range cases), round-trips arbitrary lengths, and
checks that message length is bound into the challenge. Differential tests
confirm Keylab's signatures are byte-identical to libsecp256k1's for the same
`aux_rand`.

## BIP-327 MuSig2 key aggregation (`keylab.ec.musig2`)

Implemented: `key_sort`, `key_agg` (returns `KeyAggContext` with the
aggregate point and `gacc`/`tacc` accumulators), `key_agg_coeff`,
`get_second_key`, `apply_tweak` (plain and x-only), and `key_agg_and_tweak`.
Inputs are 33-byte compressed keys; invalid keys raise
`InvalidContributionError(signer, "pubkey")`.

**Not implemented, deliberately**: nonce generation, nonce aggregation, and
partial signing. Those steps hold secret nonce state whose reuse leaks the
signing key; they belong in a hardened implementation (libsecp256k1's
`musig` module), not a teaching port.

**Legacy mode**: `advanced_suite.musig2_aggregate_keys(keys, mode="legacy-xonly")`
reproduces Keylab's earlier pre-BIP-327 draft (x-only inputs, `KeyAgg/list`
tag). Its output does not match BIP-327; it exists only to reproduce old
traces. The default is `mode="bip327"`.

**Tests**: `tests/test_musig2.py` runs the official `key_agg_vectors.json`
(valid and error cases) and `key_sort_vectors.json`.
